## 1. 개요

`jdrbmmanager`는 **HTML 파일 하나로 동작하는 북마크 관리자**입니다. 서버·빌드·외부 라이브러리 없이 `index.html`을 브라우저로 열면 바로 쓸 수 있고, 데이터는 브라우저의 `localStorage`에 저장됩니다.

| 항목 | 내용 |
|---|---|
| 구성 | `index.html` 한 파일 (CSS → HTML → JS 순서, 약 480줄) |
| 실행 | 브라우저로 `index.html` 열기 |
| 저장소 | `localStorage` (브라우저·출처별로 분리됨) |
| 외부 요청 | 파비콘 이미지(Google S2) 한 가지 |
| UI 언어 | 한국어 |

## 3. 데이터 모델과 저장소

### 북마크 항목

```js
{
  id: 1727600000000,        // number. 새 항목은 Date.now()
  title: 'GitHub',          // string, 필수
  url: 'https://github.com',// string, 필수. http(s) 스킴으로 보정됨
  category: '개발'          // string, 빈 문자열 가능
}
```

- 전역 배열 `bookmarks`가 유일한 상태이며, **배열 순서 = 화면 순서**입니다.
- 생성·수정 시각은 저장하지 않습니다.

### localStorage 키

| 키 | 값 |
|---|---|
| `single_file_bookmarks_v2` | `bookmarks` 배열 JSON |
| `single_file_bookmarks_theme` | `'light'` 또는 `'dark'` |

- 키가 없으면 시드 데이터 3개(Google, GitHub, YouTube)로 시작합니다. 모두 삭제하면 `[]`가 저장되므로 시드가 다시 나타나지 않습니다.
- 키 이름의 `_v2`는 이전 형식이 있었음을 암시하지만, 마이그레이션 코드는 없습니다.

## 4. 결정 목록

각 항목 형식: **상태** · 맥락 · 결정 · 결과(장점 / 대가).

### D-001. 단일 HTML 파일, 외부 의존성 없음
- **상태:** 추정 (README에 명시된 목표와 일치)
- **맥락:** 설치·빌드 없이 어디서나 열 수 있는 개인용 도구.
- **결정:** CSS·JS를 모두 `index.html`에 인라인. 라이브러리·번들러·패키지 매니저를 쓰지 않음.
- **결과:** 파일 하나만 복사하면 배포 끝. 대신 모듈 분리·자동 테스트·린트가 없고, 파일이 커질수록 탐색이 어려워짐.

### D-002. localStorage에 저장
- **상태:** 추정
- **맥락:** 서버가 없으므로 브라우저 내장 저장소가 유일한 선택지.
- **결정:** 변경 시마다 배열 전체를 `localStorage`에 JSON으로 저장 (`syncAndRender`).
- **결과:** 단순하고 즉시 저장됨. 대신 기기·브라우저 간 동기화가 없고, 사이트 데이터 삭제 시 함께 사라짐 → JSON 백업 기능(D-010)으로 보완.

### D-003. ID는 `Date.now()` 숫자
- **상태:** 추정
- **결정:** 새 북마크 ID를 생성 시각(ms)으로 사용.
- **결과:** 별도 카운터 없이 사실상 고유. 대신 가져온 데이터의 ID는 검증하지 않아 중복·문자열 ID가 섞일 수 있음 (5장 참조).

### D-004. 새 북마크는 목록 맨 앞에 추가
- **상태:** 추정 (코드 주석 "신규 북마크는 최상단에 추가")
- **결과:** 방금 추가한 항목을 바로 볼 수 있음. JSON 병합 시에도 가져온 항목이 앞에 붙어 같은 규칙을 따름.

### D-005. 매번 전체 다시 그리기 (innerHTML 템플릿)
- **상태:** 추정
- **결정:** 상태가 바뀌면 그리드를 비우고 모든 카드를 템플릿 문자열로 다시 생성. 사용자 텍스트는 `escapeHtml`로 처리.
- **결과:** 상태와 화면이 항상 일치하고 코드가 짧음. 수천 개 규모에서는 느려질 수 있고, 템플릿에 값을 넣을 때마다 이스케이프를 빠뜨릴 위험이 있음 (실제로 `href`에서 누락, 5장).

### D-006. HTML5 네이티브 드래그 앤 드롭, 전체 배열 기준 재배치
- **상태:** 추정
- **결정:** 카드 전체를 `draggable`로 두고, 드롭 시 **필터와 무관하게 전체 배열**에서 대상 위치로 이동.
- **결과:** 라이브러리 없이 구현. 필터 중에도 동작함. 대신 터치 기기와 키보드로는 순서를 바꿀 수 없고, 카드 텍스트 선택이 막힘(`user-select: none`).

### D-007. CSS 변수 기반 테마, `data-theme` 속성
- **상태:** 추정
- **결정:** 색상을 `:root`(라이트)와 `[data-theme="dark"]`에 변수로 정의하고 `<html>`의 `data-theme`로 전환. 첫 방문 시 `prefers-color-scheme`을 따름.
- **결과:** 테마 추가·수정이 변수만으로 가능. 첫 방문 때 OS 값이 곧바로 저장되므로 이후 OS 테마를 바꿔도 따라가지 않음.

### D-008. 파비콘은 Google S2 서비스 사용
- **상태:** 추정
- **결정:** `https://www.google.com/s2/favicons?domain=…&sz=64`로 아이콘을 불러오고, 실패하면 이미지를 숨김.
- **결과:** 사이트별 파비콘 경로를 몰라도 됨. 대신 저장된 모든 도메인이 Google로 전송되고, 오프라인에서는 아이콘이 보이지 않음. "외부 의존성 없음"(D-001)의 유일한 예외.

### D-009. HTML 내보내기는 Netscape 북마크 형식
- **상태:** 추정 (README의 "browser-compatible HTML export")
- **결정:** 크롬·파이어폭스·엣지가 가져올 수 있는 `NETSCAPE-Bookmark-file-1` 형식으로 출력. 카테고리 → 1단계 폴더, 카테고리가 없으면 `기본 북마크` 폴더.
- **결과:** 브라우저로 옮기기 쉬움. 생성 시각을 저장하지 않으므로 `ADD_DATE`는 모두 내보낸 시각.

### D-010. JSON 백업/복구, 덮어쓰기 또는 병합
- **상태:** 추정
- **결정:** 백업은 배열을 그대로 출력. 복구 시 `confirm` 한 번으로 [확인]=덮어쓰기, [취소]=병합을 선택.
- **결과:** 추가 UI 없이 두 방식 제공. 대신 "취소"가 병합을 뜻해 헷갈리기 쉽고, 병합 시 중복 검사를 하지 않음.

### D-011. 스킴 없는 URL은 `https://`로 보정
- **상태:** 추정
- **결과:** `github.com`처럼 입력해도 동작. 보정 뒤에도 `http(s)`가 아니면 저장을 거부함(D-014).

### D-012. 인라인 이벤트 핸들러와 전역 함수
- **상태:** 추정
- **결정:** 정적 마크업은 `onclick="…"`과 전역 함수로 이벤트 연결. 카드처럼 데이터로 만드는 요소는 `addEventListener`로 연결 (K-02 수정 이후).
- **결과:** 마크업만 보고 동작을 알 수 있음. 대신 모든 함수가 전역임. 데이터 값을 인라인 핸들러에 넣으면 코드로 해석되므로 금지(CLAUDE.md).

### D-013. UI 문구는 한국어, 알림은 `alert`/`confirm`
- **상태:** 추정
- **결과:** 구현이 간단함. 브라우저 기본 대화상자라 모양을 바꿀 수 없음.

### D-014. 외부 입력은 검증 후에만 상태에 넣는다
- **상태:** 확정
- **날짜:** 2026-09-29
- **맥락:** 복구한 JSON과 `localStorage` 값을 그대로 쓰면서 스크립트 주입(K-01~K-03)과 앱 정지(K-04)가 가능했음.
- **결정:**
  - `localStorage` 불러오기, JSON 복구, 모달 저장 세 경로 모두 `sanitizeBookmarks`/`isSafeUrl`로 검증한다.
  - 유효한 항목 = 제목이 비어 있지 않은 문자열이고 URL이 `http:`/`https:`. 아닌 항목은 **버린다**(복구 시 건너뛴 개수를 알림).
  - ID는 양의 정수로 정규화하고(`"7"` → `7`), 잘못되거나 없는 ID는 기존 최대값 이후로 새로 발급한다. 새 북마크 ID도 `max(Date.now(), 최대 ID + 1)`.
  - `localStorage` 값이 JSON이 아니거나 배열이 아니면 시드 데이터로 시작하되, 원래 문자열을 `single_file_bookmarks_v2_broken` 키에 보관한다.
  - 렌더링 시 `href`·`src` 속성값도 `escapeHtml`로 처리하고, 카드 버튼은 인라인 `onclick` 대신 클로저로 연결한다.
- **결과:** 외부 데이터로 스크립트를 실행하거나 앱을 멈출 수 없음. 대신 형식이 틀린 항목은 조용히 사라지고(불러오기 시), 스킴이 `http(s)`가 아닌 북마크(예: `ftp:`, `file:`)는 더 이상 저장할 수 없음.

## 6. 새 결정 추가 방법

설계에 영향을 주는 변경(저장 형식, 외부 요청, 의존성, 데이터 모델, 주요 UX 규칙)을 할 때 아래 형식으로 4장 끝에 추가합니다. 기존 결정을 뒤집을 때는 지우지 말고 상태를 `대체됨 → D-0NN`으로 바꿉니다.

```markdown
### D-0NN. 제목
- **상태:** 제안 | 확정 | 대체됨 → D-0NN
- **날짜:** YYYY-MM-DD
- **맥락:** 왜 결정이 필요했나
- **결정:** 무엇을 하기로 했나
- **결과:** 얻는 것 / 치르는 대가
```
